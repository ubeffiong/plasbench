    Advanced

    Version control

    Git without the command line, for your runs: each study is its own repository, with the study's record, sample sheets, settings, result tables, reports, figures and logs, its own history and its own remote. The PlasBench program itself is not tracked here, because updates replace it. A managed .gitignore keeps raw sequence data (reads, assemblies, FASTA, alignments), tmp folders and credentials out. Every commit is checked for data, secrets and files too large for GitHub before it is made, and nothing is ever force-pushed.

    Benchmark

    Your own isolates

    Add an isolate you sequenced: its paired short reads and a complete reference assembly (the truth). PlasBench copies or links the files into place, drafts the truth table, and adds a row to your sample sheet. Then benchmark the sheet from New benchmark.

    What you need per isolate
    • Paired Illumina reads (_1 and _2 FASTQ, gzipped is fine)
    • A complete reference: chromosome and plasmids as separate records, ideally long-read first
    • Optionally, an NCBI sequence report to label replicons
    Check the drafted truth.tsv before scoring: every PLASMID / CHROMOSOME label is what the tools are judged against.

        What it does
        
  
        You describe your tool once: what it is, how to install it, the command that runs it, and where its answer is. PlasBench then treats it like a built-in tool:
        
  
        1. Install: it gets its own environment (plasbench-<name>), so it never breaks the other tools.
          2. 
   
        2. Run: on every sample, with that sample's own assembly, reads and a fresh output folder.
          3. 
   
        3. Convert: its output is turned into PlasBench's standard prediction (which contigs are plasmid, grouped into which plasmids).
          4. 
   
        4. Score and report: it is scored against the same truth, ranked and plotted beside the built-in tools, marked "user-supplied".
        
  
        The description is a small text file, plasbench-tool.ini. This form writes it for you, and the box on the right shows it as you type. You never edit PlasBench's own code.
        

  
        Before you start: four things to know about your tool
        
  
        QuestionWhere it goesExample
        
   
        How is it installed? A conda/bioconda package, a pip package, or your own install script?How to install itmob_suite=3.1.9 from bioconda
        
   
        What is the exact command that runs it on one assembly?How to run itmob_recon --infile contigs.fasta --outdir out
        
   
        Which file holds its answer, and what does it look like?How to read its outputone FASTA per plasmid: out/plasmid_*.fasta
        
   
        Does it name contigs exactly as the assembly does?Contig id optionsNODE_1, not NODE_1_length_5000_cov_12
        
  
        Run it once by hand on one assembly first (the Terminal tab of the console works). Seeing its output folder makes the last two answers obvious.
        

  
        The five sections of the form, top to bottom
        
  
        
   
        1 · What it is
        Name: lower-case letters, digits and _; it cannot be a built-in tool's name. It becomes the tool's id everywhere (my_mob_recon). Task: reconstruction if it groups contigs into separate plasmids, which gives bin-level metrics; classification if it only says plasmid or chromosome per contig. Analysis track: short_read for tools working from Illumina assemblies. Tools are ranked only against tools on the same track. Version command: its first line of output is recorded as the version in the report.
        
   
        2 · How to install it
        conda: list the packages with versions; channels default to conda-forge and bioconda. pip: a Python package. script: your own install.sh placed next to the manifest. none: already on your PATH, or you only import results. Verify command is run after installing and by plasbench check; anything that exits 0 when the tool works, such as --help.
        
   
        3 · Reference database
        Say yes if the tool compares contigs to a plasmid database (PLSDB, MOB-suite's, ...). PlasBench then checks whether the test genomes are inside that database, which would inflate the score. Database path is what {db} means in the command.
        
   
        4 · How to run it
        Write the command for one sample using placeholders instead of file names. Click a placeholder chip to insert it. Tick the inputs it requires: a sample missing one, for example without long reads, is skipped with that reason rather than failing. Every value is safely quoted for you, so spaces in paths are fine. A long command may continue on indented lines.
        
   
        5 · How to read its output
        Pick the format that matches what the tool writes, then give the output path relative to {outdir}. For tables, say which column holds the contig and which holds the bin or label (by header name, or by number starting at 1).
        
  
        The Check box updates as you type and lists anything still to fix. When it says Valid manifest, press Save & install. The tool is saved in ~/.plasbench/tools/<name>/ and installed, and the progress shows in the console.
        
  
        Then benchmark it: on New benchmark, step Tools, tick it under Your tools. It also appears on the Tools page, where a switch sets whether it runs by default. From a terminal, the same is plasbench run --cohort public-v1 --tool my_mob_recon.
        

  
        Placeholders: what PlasBench puts in the command for each sample
        
  
        WriteIt becomes
        
   
        {contigs}the sample's assembled contigs (FASTA), the same assembly every tool is scored on
        
   
        {graph}the sample's assembly graph (GFA), for graph-based binners
        
   
        {reads_1} {reads_2}the trimmed Illumina reads, mate 1 and mate 2 (FASTQ.gz)
        
   
        {long_reads}the sample's long reads (FASTQ.gz), for long-read and hybrid tools
        
   
        {outdir}an empty folder for this tool and this sample: write everything here
        
   
        {threads} · {sample}the thread count for the tool · the sample's id
        
   
        {db} · {tool_dir}the database path from section 3 · the folder holding the manifest (for scripts you ship with it)
        

  
        Output formats: pick the one that looks like your tool's answer
        
  
        FormatThe tool writesYou fill in
        
   
        fasta_dira folder with one FASTA file per predicted plasmidthe folder (Output path) and which files (FASTA file patterns)
        
   
        plasmid_fastaone FASTA with all plasmid contigs (no grouping)the file
        
   
        contig_binsa table: contig, and the plasmid (bin) it belongs tothe file, delimiter, header, contig column, bin column
        
   
        contig_labelsa table: contig, plasmid/chromosome label and/or a probabilitylabel column and the values meaning plasmid, or a probability column and threshold. A probability also gives a precision-recall curve.
        
   
        adapteranything elsea small script of yours that converts it (see the guide ADDING_TOOLS.md)
        
  
        Contig ids must match the assembly. If the tool rewrites them, use Contig id: first_token, which keeps the first word, or Strip from contig ids, a pattern removed from each id such as _length_.*$.
        

  
        Worked example: adding MOB-recon as if it were your own tool
        
  
        MOB-recon (from MOB-suite) is already built in. Adding it again under another name is a safe way to learn the form, because you can compare your copy with the built-in result: they should score the same. Run by hand, it looks like this:
        
  
        $mob_recon --infile contigs.fasta --outdir out --num_threads 8 --force
        
  
        and it writes out/chromosome.fasta, out/contig_report.txt and one out/plasmid_<cluster>.fasta per plasmid it reconstructed. One FASTA per plasmid is exactly the fasta_dir format. So, section by section:
        
  
        SectionFieldValueWhy
        
   
        1 What it isNamemy_mob_reconmob_recon is taken by the built-in
        
   
        Taskreconstructionit groups contigs into plasmids
        
   
        Analysis trackshort_readit works on Illumina assemblies
        
   
        Version commandmob_recon --versionrecorded in the report
        
   
        2 InstallMethodcondait is a bioconda package
        
   
        Conda packagesmob_suite=3.1.9 python=3.10 pandas<=1.5.3 numpy<1.23.5the versions PlasBench pins for its built-in copy, known to work together
        
   
        Verify commandmob_recon --helpexits 0 when installed
        
   
        3 DatabaseSearches a plasmid databaseyesMOB-suite matches contigs to its plasmid database, so the leakage check applies
        
   
        4 RunCommandmob_recon --infile {contigs} --outdir {outdir}/mob --num_threads {threads} --forcethe hand-run command with the file names replaced by placeholders
        
   
        Required inputscontigsit needs only the assembly
        
   
        5 OutputOutput formatfasta_dirone FASTA per plasmid
        
   
        Output pathmobthe {outdir}/mob folder from the command
        
   
        FASTA file patternsplasmid_*.fastaonly the plasmid files, not chromosome.fasta
        
  
        The finished manifest, which is exactly what the box on the right will show:
        
  
        [tool]
name = my_mob_recon
display_name = MOB-recon (my copy)
task = binning_reconstruction
analysis_track = short_read
description = MOB-suite's plasmid reconstruction, added as a user tool
citation = Robertson & Nash (2018) Microbial Genomics. doi:10.1099/mgen.0.000206
version_command = mob_recon --version

[install]
method = conda
packages = mob_suite=3.1.9 python=3.10 pandas<=1.5.3 numpy<1.23.5
channels = conda-forge, bioconda
verify_command = mob_recon --help

[database]
uses_reference_database = yes
database = MOB-suite plasmid database

[run]
mode = command
command = mob_recon --infile {contigs} --outdir {outdir}/mob --num_threads {threads} --force
requires = contigs

[output]
format = fasta_dir
path = mob
fasta_glob = plasmid_*.fasta

        
  
        1. Press Load this example below. The form fills in, and the Check box should say Valid manifest.
          2. 
   
        2. Press Save & install. The conda environment plasbench-my_mob_recon is created; follow it in the console.
          3. 
   
        3. MOB-suite needs its database once: in the Terminal tab, run conda run -n plasbench-my_mob_recon mob_init. Skip this if the built-in MOB-recon is already set up.
          4. 
   
        4. New benchmark → Tools → tick my_mob_recon under Your tools → run. In the report it appears as "MOB-recon (my copy)", marked user-supplied, next to the built-in MOB-recon.
        

  
        You already ran the tool: import its results instead
        
  
        Set How it runs to import, set Install method to none, and give the Outputs folder and a File name pattern containing {sample}, such as {sample}.tsv, with one file per sample. Then fill in the output format as above. PlasBench runs nothing and scores what you give it. The files must come from the same assemblies PlasBench scores, so the contig ids match.
