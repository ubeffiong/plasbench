    Tools

    Every tool PlasBench can benchmark, built-in and your own. The switch, and the on / off beside it, set whether a tool runs by default: on means it runs unless you turn it off for a run, off means it is skipped unless you turn it on (saved for this computer). The New benchmark page can still change it for one run.

    Three kinds of task, each ranked on its own. Classification: the tool labels every contig plasmid or chromosome (ranked by base-level F1). Binning reconstruction: the tool groups contigs into separate plasmids (ranked by length-weighted binning F1). Sequence reassembly: the tool produces the plasmid sequences themselves (ranked by CPRR, the share of true plasmids recovered correctly). Tools are never ranked against tools of another task or another input track.

    Scoring decisions

    Before any result is looked at, PlasBench fixes how tools are scored and ranked. These are those rules, each in plain words. They are confirmed and recorded so that nobody, including you, can quietly change a rule after seeing which tool wins. You can still change one: PlasBench asks why, records it, and warns that results from before and after the change cannot be compared.

      Version control

      Git without the command line, for your runs: one repository in the working directory, holding every study's record, sample sheets, settings, result tables, reports, figures and logs, with one history and one remote. The PlasBench program itself is not tracked here, because updates replace it. A managed .gitignore keeps raw sequence data (reads, assemblies, FASTA, alignments), tmp folders and credentials out.       Benchmark

      Your own isolates

      Tell PlasBench which folder(s) hold your reads and reference genomes. It finds each isolate, places the files where the run expects them, and tests that it can read and use them, before any run spends hours. Not sure what you need? Read the guide.

      1. Get a sheet to fill in (optional)

      You do not have to write a sheet: step 2 writes it for you from your folders. If you prefer to fill one in yourself, download a template. Each has the rules written at the top, and a worked example.

      What you need for each isolate: its paired Illumina reads (two files); for a scored benchmark also the complete genome of the same isolate (chromosome and each plasmid as separate sequences). With reads only, PlasBench reconstructs the plasmids but cannot score them.

      2. Find my files

      plasbench intake scan / stage

      Add the folder(s) where your files are. Sub-folders are searched. Nothing is changed until you press Place the selected isolates.

      3. Quick test: can PlasBench see and use them?

      plasbench intake check

      Opens each file the way a run will: are the reads real FASTQ and paired, is the reference a complete genome, do the labels match it, and do the reads actually come from that reference's isolate. Takes seconds per isolate and changes nothing unless you press Fix.

      Where each isolate's own folder lives. The default is PlasBench's data folder.

      Scan a folder

      plasbench scan-isolates

      Point at ONE folder, even a messy one with sub-folders and unrelated files. PlasBench looks for each isolate's paired reads and its complete reference, shows what it would use and why, and flags anything it is not sure of. Scanning never changes your folder, and nothing is added until you press Add selected isolates.

      What is recognised
      • Reads: FASTQ pairs named _R1/_R2, _1/_2, .1/.2 or _R1_001/_R2_001 (.fastq or .fq, gzipped). Illumina lanes (_L001, _L002) of one isolate are listed and flagged: you confirm before they are joined.
      • Reference: a plain FASTA of the complete genome. Assembler output (contigs.fasta, scaffolds.fasta, assembly.fasta in SPAdes, Unicycler or Flye folders, NODE_ headers) is never taken as a reference.
      • Also used: sequence_report.jsonl and truth tables (truth.tsv) that sit with an isolate.
      • Ignored and counted: alignments (BAM), documents, spreadsheets, logs, hidden folders, .git, results and logs folders, long reads (not used here).
      • Limits: matching uses folder and file names; check the reference of every isolate marked "check" before you rely on it.

      Results folders

      How to read a rank. A rank is a tool's position within one task and one input track (short-read, long-read or hybrid), ordered by that task's headline metric (F1 for classification, length-weighted binning F1 for binning, CPRR for reassembly). Rank 1 is the best score, but a tied or overlapping confidence interval means two tools cannot be told apart, and a tool is only ranked on the isolates it ran on. "Leading" names the rank-1 tool of each task; the full table is in the report and the Leaderboard download. A run that says "Completed with warnings" finished normally but had failed tool runs.

          What it does
          
  
          You describe your tool once: what it is, how to install it, the command that runs it, and where its answer is. PlasBench then treats it like a built-in tool:
          
  
          1. Install: it gets its own environment (plasbench-<name>), so it never breaks the other tools.
            2. 
   
          2. Run: on every sample, with that sample's own assembly, reads and a fresh output folder.
            3. 
   
          3. Convert: its output is turned into PlasBench's standard prediction (which contigs are plasmid, grouped into which plasmids).
            4. 
   
          4. Score and report: it is scored against the same truth, ranked and plotted beside the built-in tools, marked "user-supplied".
          
  
          The description is a small text file, plasbench-tool.ini. This form writes it for you, and the box on the right shows it as you type. You never edit PlasBench's own code.
          

  
          Before you start: four things to know about your tool
          
  
          QuestionWhere it goesExample
          
   
          How is it installed? A conda/bioconda package, a pip package, or your own install script?How to install itmob_suite=3.1.9 from bioconda
          
   
          What is the exact command that runs it on one assembly?How to run itmob_recon --infile contigs.fasta --outdir out
          
   
          Which file holds its answer, and what does it look like?How to read its outputone FASTA per plasmid: out/plasmid_*.fasta
          
   
          Does it name contigs exactly as the assembly does?Contig id optionsNODE_1, not NODE_1_length_5000_cov_12
          
  
          Run it once by hand on one assembly first (the Terminal tab of the console works). Seeing its output folder makes the last two answers obvious.
          

  
          The five sections of the form, top to bottom
          
  
          
   
          1 · What it is
          Name: lower-case letters, digits and _; it cannot be a built-in tool's name. It becomes the tool's id everywhere (my_mob_recon). Task: choose one or more. Binning reconstruction groups contigs into separate plasmids, which gives bin-level metrics; classification says plasmid or chromosome per contig; sequence reassembly produces plasmid sequences. The first task is the primary one; the others are extra tasks the tool is also scored on, when its output allows (see Several tasks and outputs). Analysis track: short_read for tools working from Illumina assemblies. Tools are ranked only against tools on the same track. Version command: its first line of output is recorded as the version in the report.
          
   
          2 · Where it comes from
          Pick a Source: already installed (on your PATH), a package manager (conda: list the packages with versions; pip: a Python package), a download from a URL, a file or folder on this computer, or your own install script (a file beside the manifest). Details below. Verify command is run after installing and by plasbench check.
          
   
          3 · Reference database
          Say yes if the tool compares contigs to a plasmid database (PLSDB, MOB-suite's, ...). PlasBench then checks whether the test genomes are inside that database, which would inflate the score. Database path is what {db} means in the command.
          
   
          4 · How to run it
          Write the command for one sample using placeholders instead of file names. Click a placeholder chip to insert it. Tick the inputs it requires: a sample missing one, for example without long reads, is skipped with that reason rather than failing. Every value is safely quoted for you, so spaces in paths are fine. A long command may continue on indented lines.
          
   
          5 · How to read its output
          Add one output row for each kind of file the tool writes. In each row pick the format that matches what the tool writes, then give the path relative to {outdir}. Only the settings that format needs are shown: for tables, which column holds the contig and which holds the bin or label (by header name, or by number starting at 1). If you would rather not describe it, choose Detect automatically and list candidate file patterns.
          
  
          The Check box updates as you type and lists anything still to fix. When it says Valid manifest, press Save & install. The tool is saved in ~/.plasbench/tools/<name>/ and installed, and the progress shows in the console.
          
  
          Then benchmark it: on New benchmark, step Tools, tick it under Your tools. It also appears on the Tools page, where a switch sets whether it runs by default. From a terminal, the same is plasbench run --cohort public-v1 --tool my_mob_recon.
          

  
          One tool, several tasks and outputs
          
  
          Choose more than one Task when a tool can be judged on more than one. A binner, for example, can be scored as a binner and, by reading a contig that sits in a bin as a plasmid contig, as a classifier. Beside each task in the Task box, and in the Check box, PlasBench says how it gets that task's result from what you described:
          
  
          StatusMeaning
          
   
          nativethe output you described already is that task's result
          
   
          derived from <output>the result is worked out from another output; the How column names the rule
          
   
          not possible: <reason>the output cannot give that task (for example plasmid labels cannot say which plasmid a contig belongs to). It is still selectable so you can read the reason; add an output that can, or remove the task.
          
  
          A tool may also write more than one output: add a row for each. In the manifest, one output is a plain [output] section; several become format = contig_bins, plasmid_fasta with a [output.contig_bins] and a [output.plasmid_fasta] section. If PlasBench is told Detect automatically, it is format = auto with candidates = bins.tsv, *.labels.tsv. A pattern that matches files of different shapes is reported as ambiguous, with the fix, instead of guessed. Each format can appear once.

          Worked example: adding MOB-recon as if it were your own tool
          
  
          MOB-recon (from MOB-suite) is already built in. Adding it again under another name is a safe way to learn the form, because you can compare your copy with the built-in result: they should score the same. Run by hand, it looks like this:
          
  
          $mob_recon --infile contigs.fasta --outdir out --num_threads 8 --force
          
  
          and it writes out/chromosome.fasta, out/contig_report.txt and one out/plasmid_<cluster>.fasta per plasmid it reconstructed. One FASTA per plasmid is exactly the fasta_dir format. So, section by section:
          
  
          SectionFieldValueWhy
          
   
          1 What it isNamemy_mob_reconmob_recon is taken by the built-in
          
   
          Taskbinning reconstructionit groups contigs into plasmids
          
   
          Analysis trackshort_readit works on Illumina assemblies
          
   
          Version commandmob_recon --versionrecorded in the report
          
   
          2 InstallMethodcondait is a bioconda package
          
   
          Conda packagesmob_suite=3.1.9 python=3.10 pandas<=1.5.3 numpy<1.23.5the versions PlasBench pins for its built-in copy, known to work together
          
   
          Verify commandmob_recon --helpexits 0 when installed
          
   
          3 DatabaseSearches a plasmid databaseyesMOB-suite matches contigs to its plasmid database, so the leakage check applies
          
   
          4 RunCommandmob_recon --infile {contigs} --outdir {outdir}/mob --num_threads {threads} --forcethe hand-run command with the file names replaced by placeholders
          
   
          Required inputscontigsit needs only the assembly
          
   
          5 OutputOutput formatfasta_dirone FASTA per plasmid
          
   
          Output pathmobthe {outdir}/mob folder from the command
          
   
          FASTA file patternsplasmid_*.fastaonly the plasmid files, not chromosome.fasta
          
  
          The finished manifest, which is exactly what the box on the right will show:
          
  
          [tool]
name = my_mob_recon
display_name = MOB-recon (my copy)

          Example: a binner that is also scored as a classifier
          
  
          A binner writes a table of contig and bin. That one output is a native result for binning reconstruction, and the same table derives classification: a contig in a bin is a plasmid contig. So the task list is binning_reconstruction, classification (binning is primary) with one contig_bins output.
          
  
          [tool]
name = my_binner
display_name = My binner (also scored as a classifier)
task = binning_reconstruction, classification
analysis_track = short_read
description = A contig binner, scored as a binner and as a plasmid/chromosome classifier

[install]
method = conda
packages = mybinner=1.0.0
channels = conda-forge, bioconda
verify_command = mybinner --help

[run]
mode = command
command = mybinner --contigs {contigs} --out {outdir}/bins.tsv --threads {threads}
requires = contigs

[output]
format = contig_bins
path = bins.tsv
delimiter = tab
header = yes
contig_column = contig
bin_column = bin

          
  
          

  
          Example: a tool downloaded from a URL
          
  
          The tool comes from a release archive. PlasBench downloads it when you press Save & install, checks the SHA-256 if you give one, unpacks it, runs the build command, and the run command refers to it as {src}. Replace the address with the real one and paste its checksum.
          
  
          [tool]
name = my_url_tool
display_name = My tool (downloaded)
task = classification
analysis_track = short_read
description = A classifier downloaded from a release page

[install]
method = url
url = https://example.org/releases/mytool-1.2.0.tar.gz
# sha256 = paste the SHA-256 of the file here (recommended): a changed download is then refused
kind = archive
build_command = make

[run]
mode = command
command = {src}/mytool --contigs {contigs} --out {outdir}/labels.tsv --threads {threads}
requires = contigs

[output]
format = contig_labels
path = labels.tsv
contig_column = contig
label_column = label
plasmid_values = plasmid
