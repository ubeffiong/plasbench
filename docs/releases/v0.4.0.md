# PlasBench v0.4.0

A feature release that also changes how tools are scored and ranked. **Scores and rankings from v0.4.0 are not
directly comparable with v0.3.0 or earlier**: re-run the report (or the benchmark) before comparing tools across
versions. Full detail is in the [changelog](../../CHANGELOG.md#040---2026-11-15).

## What changes your results

After a second external scientific review, this release also (point by point in
[docs/reviews/SECOND_REVIEW_RESPONSE.md](../reviews/SECOND_REVIEW_RESPONSE.md)):

- **Ranks every tool in the task its output declares.** plasmidSPAdes, a reassembler, is no longer ranked as a
  contig classifier: it has its own reassembly leaderboard. `config/tool_capabilities.tsv` records each tool's
  `evaluation_task`.
- **Keeps reference quality and independence apart.** A reference polished with the benchmark's own reads no longer
  enters the primary analysis by default; a new reference-independence table shows how much each tool's result
  depends on how its references were built.
- **Uses intervals that hold their coverage with few studies.** The leaderboard and comparison intervals are now
  cluster-robust t intervals, chosen because the simulation showed the earlier percentile bootstrap was too narrow.
- **Reads comparisons by effect first.** Each paired comparison says whether it shows a practical difference,
  equivalence, or neither; a non-significant result is never reported as equal performance.
- **Scores AMR placement fairly for tools that do not bin**, and says that this is sequence attribution, not
  reconstruction.
- **Validates per-isolate recommendation harder:** clonal-group and species holdouts, taxonomy-aware neighbours,
  abstention outside the training data, and an operational model that stays off until it has shown value and
  calibrated uncertainty out of study.

- **Permutation tests need six independent units** (BioProject clusters when the sample sheet records them) and
  are exact for small designs. A comparison with fewer is reported as underpowered, and the report says the
  smallest Holm-adjusted p the run can reach.
- **The primary analysis is never a silent fallback.** With no Tier 1-2 reference the ranking is labelled
  *provisional* everywhere (leaderboard, banner, report). `--allow-primary-fallback` keeps the old behaviour with
  a warning. The bundled public-v3 cohort and the demo are in this state.
- **The recommendation model uses truth-free features only** (read depth, the isolate's own assembly, tool,
  organism, Gram group). A saved model that used truth-derived features is refused with the refit instruction.
- **CPRR, SV-PRR and AMR context follow one identity rule**: on isolates whose truth was polished with the
  benchmark's own reads, the identity criterion is left out.
- **Burden columns are blank, not 0, when they were not measured**, and the perfect-recovery label stays
  *not assessed* in that case.

## New

- **Correct plasmid reconstruction rate (CPRR)** per isolate, with **SV-PRR** and the structural calls beside it.
- **AMR plasmid context**: AMR-PRR, flank context and resistance-gene pairs kept together, plus a gated step to
  promote draft AMR truth to curated truth. A draft file is never counted as curated.
- **Burden of unverified predicted sequence** in the leaderboard and report: unmapped, off-truth, and plasmid +
  chromosome bases beside strict precision.
- **Metric registry and evaluation ladder**, so every metric has one definition, source and column.
- **Truth audits and an evidence record per reference**: chromid, integrated-plasmid, multimer and marker-free
  flags, marker-database overlap, and six declared, inferred or unknown evidence fields per reference.
- **Real-binary checks, database provenance and validation tiers**: each tool is shown as *real binary checked*,
  *adapter tested* or *untested*. Each database records its version, source, date and checksum; a missing value is
  shown as *not recorded*, never guessed.
- **Report figures**: a numeric tool-by-metric heatmap, a radar fingerprint per tool, complexity and outcome
  matrices, a recommendation evidence panel, plasmid maps with identity rings and resistance-region brackets, and
  TP/FP encodings. From the ninth tool on, tools differ by line dash or marker shape as well as colour.
- **Three-way recommender comparison**: single best tool, best per organism, and best for similar isolates. The
  recommendation says which won.
- **Dataset characteristics**: one table per run, each column marked *knowable without a reference* or *needs the
  reference*.
- **Ranking sensitivity** now covers alignment length, the headline endpoints and the CPRR thresholds.

## Using PlasBench

- **Study folders.** Each benchmark keeps everything it produces in `<workspace>/<study>/`. Downloads, tool
  environments and databases stay shared between studies.
- **Databases are downloaded once per computer and reused.** The window shows whether each database is installed
  and where. Database paths are an optional fold, *Use a different database copy*: leave them empty and the
  installed copy is used.
- **One `PlasBench` folder, updated in place** by `./update.sh` or `plasbench upgrade`.
- **The window** gains Workspace & studies, Version control, a terminal and a session log. Warnings show in
  yellow and errors in red.
- **Runs never stop silently.** Every stop is reported on the console and in `logs/run_errors.log`. A run cut off
  during assembly resumes cleanly, and stage 2 (truth) is faster, parallel and resumable.

## Upgrading from v0.3.0

From your PlasBench folder:

```bash
./update.sh
```

On an older versioned install (`~/plasbench-0.3.0` or earlier), run `./update.sh` there, or install again:

```bash
cd ~ && curl -fL -O https://raw.githubusercontent.com/ubeffiong/plasbench/main/scripts/install_latest.sh && bash install_latest.sh
```

No tool, Conda package or database changed, so nothing needs reinstalling or downloading again. Your studies,
settings, own tools, downloads and databases are kept. Rebuild a report with the new figures and labels with
`plasbench report --study NAME`.
