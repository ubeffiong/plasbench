# PlasBench v0.1.5

Released 2026-09-10.

## Highlights

### Optional operational-mode plasmid novelty classification

For a truth-unknown sample, `plasbench reconstruct` can now also answer a
different question than tool selection: is this isolate's own reconstructed
plasmid similar to anything PlasBench has a reference for, or does it look
genuinely novel? This independently reimplements santirdnd/COPLA's own
known-cluster-or-novel pattern (similarity to a reference set, then a
membership call with a confidence score) using `mash` -- already a direct
PlasBench dependency -- against a small, PlasBench-curated reference set,
rather than COPLA's own code or its `graph-tool`/nested-SBM machinery.

- **Off by default** (`RUN_PLASMID_NOVELTY_CLASSIFICATION=0`). It is an
  operational-only signal: never computed for a benchmark isolate that has
  truth, and its output is never wired into `recommendation_model.py`'s
  training features -- a genuinely unknown isolate has no truth reference,
  which is the entire reason this signal exists in the first place; feeding
  it back into the model would be leakage, not a real feature.
- One-time setup builds the reference Mash sketch from a committed, curated
  accession list:
  ```bash
  python3 python/build_plasmid_reference_set.py \
      --accessions cohorts/reference_plasmids/curated_accessions.tsv \
      --out-dir data/db/plasmid_reference
  ```
  The curated set starts small and deliberately: 16 real, verified NCBI
  plasmids spanning *E. coli*, *Salmonella enterica*, *Klebsiella
  pneumoniae*, *Acinetobacter baumannii*, and *Staphylococcus aureus*
  (`cohorts/reference_plasmids/curated_accessions.tsv` records exactly which,
  with a one-line justification for each).
- Then enable it for reconstruction:
  ```bash
  RUN_PLASMID_NOVELTY_CLASSIFICATION=1 plasbench reconstruct --sample new_isolate_01 \
    --sra SRR12345678 --organism "Klebsiella pneumoniae" --gram-group Gram_negative
  ```
- A `known_cluster` call means the nearest reference is within
  `PLASMID_NOVELTY_SIMILARITY_THRESHOLD` (default Mash distance 0.05,
  roughly ANI >= 95%) AND that reference's own cluster has at least
  `PLASMID_NOVELTY_MIN_CLUSTER_MEMBERS` members (default 2); anything else is
  `novel`. A missing `mash` binary or reference set gives
  `insufficient_reference` rather than guessing either way.
- Results land in `results/<sample>/plasmid_similarity.tsv` and under
  `plasmid_novelty` in `selection_report.json` -- a supplementary signal
  alongside tool selection, not a gate on it: a failed or skipped
  classification never blocks reconstruction or the rest of the report.

See `docs/OPERATIONAL_SELECTION.md`'s "Novel-vs-known plasmid classification"
section for the full walkthrough.

Two real, permanent Zenodo dataset DOIs minted when the v0.1.3/v0.1.4 GitHub
Releases were created during the v0.1.x renumbering are now recorded in
their release notes and in `cohorts/README.md`, per `docs/RELEASING.md`'s

[10.5281/zenodo.22671309](https://doi.org/10.5281/zenodo.22671309) (v0.1.3),
[10.5281/zenodo.22671314](https://doi.org/10.5281/zenodo.22671314) (v0.1.4).
These are dataset-only DOIs for the archived `cohorts/*.tsv`, not a software
citation.

### PyPI publishing removed

`.github/workflows/release.yml`'s PyPI Trusted Publishing step has been
failing on every real attempt with `invalid-publisher`; the public PyPI API
confirms `plasbench` has never actually existed at
pypi.org/project/plasbench despite `continue-on-error` making the release
job show green every time. Removed rather than left as a step that always
fails silently -- the GitHub Release archive (below) is the Python-package
distribution. See `RELEASING.md` for how to re-add PyPI later with a
verified trusted publisher.

## Install or upgrade

```bash
sha256sum -c plasbench-0.1.5.tar.gz.sha256
```

Existing installations: `plasbench upgrade`.

## Container

```bash
docker pull ghcr.io/ubeffiong/plasbench:v0.1.5
docker run --rm ghcr.io/ubeffiong/plasbench:v0.1.5 plasbench --version
```
