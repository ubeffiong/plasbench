## The first-attempt tail log, and why it is kept

`scratchpad/tail_all.log` was the first tail-section run. It shows about 100 `FAIL ... rc=2` lines. **Those are not test failures.** The loop that produced it ran every test file with `bash`, so every Python test (`*.py`) failed with a shell syntax error, and the loop shared its standard input with the tests, so some tests consumed part of the list. Three failures in it were genuine, and each was fixed before the release:

| Test | Why it failed | Fix |
|---|---|---|
| `test_operational_reconstruct.sh` | The stage-4 database pre-flight (new in this release) refuses to launch a tool whose database folder is missing; the test's stubbed Platon had none | The test gives the stub a database folder |
| `test_parallel_execution.sh` | Same | Same |
| `test_stage8_fresh_prediction.sh` | Same | Same |

The log is kept unedited (with a header saying it is invalid) so the record shows what was run, not only the clean result. The corrected run above replaces it.

## What the skipped checks were

The full suite prints how many checks did not run. This release fixed the counter: it used to match every line containing the word, which counted 14 passing `SKIP set: ...` lines and printed 29. The real number is **19**:

| Count | Why it did not run | Where it runs |
|---|---|---|
| 16 | `node` is not installed in the test environment (JavaScript syntax, parity and hash tests of the report and window pages) | CI and any machine with Node |
| 2 | Opt-in real-browser tests (`PLASBENCH_BROWSER_TESTS=1`, needs Node 22+ and Chrome or Edge) | A machine with a browser |
| 1 | The PlasEval cross-check needs a PlasEval checkout (`PLASEVAL_SRC`) | A machine with that checkout |

`REQUIRE_NO_SKIPS=1 bash test/run_tests.sh` turns any skip into a failure.

## What the QA found and fixed on the way

Defects found by running the suite, all fixed before the release (none changed a score):

- **Review-ledger line references went stale** after the fixes moved lines (several rounds); the ledger test caught each one.
- **`test_job_survival` modelled a vanished runner with a cancel.** A cancel now also stops the command's process group, so the runner recorded a stop and the run read as `failed`, not `interrupted`. The test now kills the runner outright. It also had a race (one server saving the shared job index over another's new entry) and could signal process 0 if the runner's pid was not yet recorded, which would have killed the whole test runner; both are guarded.
- **Six shell tests stubbed a tool without its database** after the stage-4 pre-flight was added (`test_failed_tool_exit_code`, `test_only_tool_gating`, `test_operational_reconstruct`, `test_parallel_execution`, `test_stage8_fresh_prediction` for Platon; `test_plascope_stage` and `test_adapter_no_output` for PlaScope). Each now provides a database folder.
- **The report-surface registry was missing new outputs** (`benchmark.input_fingerprint.json` and three leaderboard columns).
- **Two wiring gaps:** stage 6 did not pass `--allow-input-mismatch`, and `relabel_cohort_provenance` was not registered as a maintenance script.
- **The skipped-check counter was inflated** (above).

## What this QA did not cover

- **A real browser.** The window and the report sandbox (Content-Security-Policy) were checked by response headers, static page checks, `node --check` where Node was available (it was not in the suite environment) and tests. They were not driven in Chrome or Edge.
- **The 16 Node-dependent and 2 browser checks** and the PlasEval cross-check (above).
- **Real tool binaries.** Only `mob_recon`, `platon` and `plasmidspades` have real-binary checks (the scheduled *Real tools* workflow); 13 tools are tested against stand-ins. The suite does not run them.
- **A fresh-machine install, native Windows, HPC schedulers and long runs.** The install, update and bootstrap scripts were exercised through their tests only.
- **A large real-data run.** `results_real_cohort1/` (10 isolates) was not rebuilt with this release, and the public-v4 independent-truth run has not been done.

## Reproduce

```bash
git archive HEAD | tar -x -C /tmp/plasbench-qa && cp -r .github /tmp/plasbench-qa/
cd /tmp/plasbench-qa && bash test/run_demo.sh && bash test/run_tests.sh
```

A clean export is used because some tests check that `plasbench/data/ui.html` is tracked by git, which a worktree under WSL cannot show. Expect `ALL PLASBENCH TESTS PASSED` and `SKIPPED CHECKS: 19` where Node is absent.
